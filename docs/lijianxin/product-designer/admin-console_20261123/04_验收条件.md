# 管理后台（admin-console）- 验收条件

- 版本：v1.0
- 创建日期：2026-11-23
- 任务 ID：20261123-003
- 说明：采用 Given-When-Then 格式。P1 功能每项至少 2 个场景，P2 功能每项至少 1 个场景。数值取自当前设计稿，`[待确认]` 项变更后需同步修改。

## F1 管理员登录与会话（P1）

**AC-F1-01 登录成功**
- Given：`admin_user` 中存在账号 `admin`，状态为启用，`failed_count = 2`
- When：提交 `POST /api/admin/auth/login`，用户名 `admin`，密码正确
- Then：返回 `code 0`，`data` 含 `token`、`expiresIn`、`admin.id`；`failed_count` 清零；`last_login_at` 更新；`admin_audit_log` 新增一条 `auth.login`

**AC-F1-02 密码错误累计锁定**
- Given：账号 `admin` 的 `failed_count = 4`
- When：连续提交第 5 次错误密码
- Then：返回 `code -1`，`message` 为 `账号或密码错误`；`locked_until` 设为当前时间 + 15 分钟 `[待确认]`；此后 15 分钟内即使密码正确，也返回 `账号已锁定，请 N 分钟后重试`

**AC-F1-03 业务端 token 不能访问后台**
- Given：用户通过业务端登录，持有 `aud` 不是 `admin` 的 JWT
- When：携带该 token 请求 `GET /api/admin/auth/me`
- Then：HTTP 401，`{code: 401, data: null}`

**AC-F1-04 修改密码后旧 token 失效**
- Given：管理员已登录，持有 token A
- When：提交 `PUT /api/admin/auth/password`，旧密码正确，新密码 `Admin2026x`（8–64 位且含字母和数字）
- Then：返回 `code 0`；`token_version + 1`；再用 token A 请求 `GET /auth/me` 返回 HTTP 401；审计新增 `auth.change_password`

**AC-F1-05 新密码不合规**
- Given：管理员已登录
- When：提交新密码 `12345678`（无字母）
- Then：返回 `code -1`，`message` 为 `密码需 8–64 位且同时包含字母和数字`；`token_version` 不变

**AC-F1-06 已禁用管理员的 token 立即失效**
- Given：管理员持有有效 token，随后其 `admin_user.status` 被置为禁用
- When：携带该 token 请求任一后台接口
- Then：HTTP 401

## F2 家庭管理（P1）

**AC-F2-01 列表搜索**
- Given：存在家庭 `张家`（编码 `F1001`，房主手机号 `13800001234`）与 `李家`
- When：`GET /families?keyword=1380000&status=1&page=1&pageSize=20`
- Then：返回包含 `张家` 的分页结果，`ownerPhone` 显示为 `138****1234`，含 `memberCount`、`dishCount`、`orderCount`；不含 `李家`

**AC-F2-02 编辑家庭名称**
- Given：家庭 ID 5 名称为 `张家`
- When：`PUT /families/5`，`{familyName: '张家小厨'}`
- Then：`family.family_name` 更新；审计新增 `family.update`，`before_data` 为 `{familyName: '张家'}`，`after_data` 为 `{familyName: '张家小厨'}`

**AC-F2-03 编辑无内容**
- Given：家庭 ID 5 存在
- When：`PUT /families/5`，请求体为 `{}`
- Then：返回 `code -1`，`message` 为 `没有可更新的内容`，不写审计

**AC-F2-04 注销前查看影响范围**
- Given：家庭 ID 5 有 4 名成员、3 个 `pending / confirmed` 订单、2 个 `published / paused` 任务、1 个 `pending` 兑换
- When：`GET /families/5/close-impact`
- Then：返回 `{memberCount: 4, openOrderCount: 3, openTaskCount: 2, pendingRewardOrderCount: 1}`

**AC-F2-05 注销家庭**
- Given：家庭 ID 5 `status = 1`
- When：`POST /families/5/close`，`{reason: '用户申请注销'}`
- Then：`family.status = 0`；审计新增 `family.close`，`before_data: {status: 1}`，`after_data: {status: 0}`，`reason` 已保存；D2 上线后，该家庭成员调用业务端家庭内接口被拒绝

**AC-F2-06 reason 过短**
- Given：家庭 ID 5 `status = 1`
- When：`POST /families/5/close`，`{reason: '123'}`（3 字）
- Then：返回 `code -1`，`message` 为 `请填写操作原因`；`family.status` 仍为 1

**AC-F2-07 重复注销与恢复正常家庭**
- Given：家庭 ID 5 已注销；家庭 ID 6 为正常状态
- When：对 5 再次 `close`；对 6 调用 `restore`
- Then：前者返回 `家庭已注销`，后者返回 `家庭未注销`；两者 `status` 均不变

**AC-F2-08 并发注销**
- Given：两名后台会话同时对家庭 ID 5 提交 `close`
- When：两个请求先后执行 `UPDATE ... WHERE id = 5 AND status = 1`
- Then：仅一个请求影响 1 行并写审计，另一个影响 0 行，返回 `家庭已注销`，审计只有一条

## F3 菜品管理（P1）

**AC-F3-01 跨家庭搜索**
- Given：家庭 5 有菜品 `红烧肉`（`stock = 0`，已上架），家庭 6 有菜品 `红烧排骨`
- When：`GET /dishes?keyword=红烧&soldOut=1`
- Then：仅返回家庭 5 的 `红烧肉`，响应项含 `familyName`、`stock: 0`

**AC-F3-02 编辑菜品价格**
- Given：菜品 ID 20 价格 `28.00`
- When：`PUT /dishes/20`，`{price: 32.5, stock: 10}`

**AC-F3-03 非法价格**

**AC-F3-04 下架菜品**

**AC-F3-05 删除被引用的菜品**

**AC-F3-06 删除未被引用的菜品**

- When：`POST /dishes/21/delete`，`{reason: '内容违规'}`
- Then：`dish` 表中该行被物理删除；审计 `dish.delete` 的 `before_data` 含该菜品完整字段；历史订单的 `order_item` 快照不受影响

## 通用验收

- 所有 `POST /…/{动作}` 高危接口缺少 `reason` 或长度不在 4–200 字时，返回 `请填写操作原因`，不改数据。
- 所有分页接口：`pageSize` 超过 100 时按 100 处理，`page` 缺省为 1。
- 后台所有响应字段均为 camelCase，时间格式 `YYYY-MM-DD HH:mm:ss`。
- 新增迁移 `2026112303_admin_console_v1.0.sql` 重复执行不报错 `[建议]`，并已同步 `jiawei_db_schema.sql` 与 `DATABASE.md`。
- 后台前端的高危操作均弹出二次确认，确认框展示操作对象与影响范围，原因输入未达 4 字时确认按钮置灰。
