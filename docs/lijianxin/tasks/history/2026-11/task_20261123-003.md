<!-- atomic-skill: code-verify -->
已核实（读代码所得）：
- JwtPayload 仅 {userId, nickname}；signToken/verifyToken 共用 config.jwt.secret，后台必须用独立 secret 或 aud 区分
- authRequired 只验签，不查 user.status；禁用用户已发 token 仍有效；login 只在登录时查 status
- requireMember/requireAdmin 不检查 family.status；getUserFamilies/getFamilyDetail 才过滤 status=1，已注销家庭的菜品等接口仍可调用
- deleteDish 为硬删除（DELETE），order_item 用快照所以历史订单不受影响；reward.dish_id 无约束，删菜品后 reward 可能悬空
- adjustPoints 注释说同步 user.points，实际只更新 family_member.points；余额在事务外读取、无行锁，并发会丢更新
- resetPassword 无验证码、仅凭账号名即可重置（业务端现有风险，后台重置需另做）
- app.ts：cors origin '*'；/api/v1 挂载地域推荐；cron 用 setTimeout+setInterval，进程内运行，无手动触发入口
- 响应格式 res.success -> {code:0,message,data}；res.fail 返回 HTTP 200 + code -1
- 表为逻辑外键，无迁移工具，迁移脚本放 server/docs/migrations/，命名 YYYYMMDDNN_xxx.sql
未核实：order cancel/complete 的积分退款细节、reward 兑换扣分逻辑
